# Hospital vital signs monitoring (Edge to Cloud)

Distributed Systems for IoT

Three simulated monitors send pulse and SpO2 readings over MQTT. Node-RED checks the values and shows alerts on a dashboard, and the readings also go to Kafka for the Cloud part. It is a simulation, there are no real patients.

## Services

- `mosquitto`: MQTT broker
- `nodered`: monitor simulator, alert logic and dashboard (one tab each)
- `kafka` and `kafka-ui`: Kafka in KRaft mode, used by the Cloud part

## MQTT topics

Readings are published every 10 s to `hospital/{ward}/room{room}/{sign}` with QoS 1.

Examples:

- `hospital/ward2/room204/pulse`
- `hospital/ward2/room204/spo2`
- `hospital/ward2/room205/pulse`
- `hospital/ward2/room205/spo2`
- `hospital/ward2/room206/pulse`
- `hospital/ward2/room206/spo2`

The timestamp is set by the simulator when the reading is generated (UTC).

Alerts go to `alerts/{ward}/room{room}` with QoS 1. Only changes are sent: ALERT when pulse is below 40 or above 140, or SpO2 is below 90, and RESOLVED when it goes back to normal.

`status/monitors` is retained and says `online`, or `offline` when Node-RED disconnects (Last Will).

### MQTT message format

Each reading is published as a JSON message with the following structure:

```json
{
  "ward": "ward2",
  "room": "204",
  "patient": "P001",
  "sign": "pulse",
  "value": 72,
  "unit": "bpm",
  "timestamp": "2026-11-13T20:35:15.271Z"
}
```

| Field | Description | Example |
|---|---|---|
| `ward` | Ward identifier | `ward2` |
| `room` | Room number | `204` |
| `patient` | Patient identifier | `P001` |
| `sign` | Type of measurement | `pulse` or `spo2` |
| `value` | Measured value | `72` |
| `unit` | Measurement unit | `bpm` or `%` |
| `timestamp` | Reading generation time in UTC (ISO 8601) | `2026-11-13T20:35:15.271Z` |

The timestamp is generated by the simulator and must be preserved by the Cloud bridge.

### Patient mapping

| Patient | Room |
|---|---|
| P001 | 204 |
| P002 | 205 |
| P003 | 206 |

### Cloud communication

The Cloud bridge subscribes to all vital-sign readings using the MQTT wildcard topic:

`hospital/+/+/+`

It forwards the received messages to the Kafka topic:

`hospital-readings`

The Kafka topic is configured with 3 partitions. The Kafka message key is the patient identifier (`patient`). This ensures that messages with the same key are consistently assigned to the same partition, preserving their order within that partition.

The original JSON payload, including its timestamp, is preserved.

Kafka is accessed using:
- From Docker containers: `kafka:29092`
- From the host machine: `localhost:9092`

## How to run

```powershell
copy .env.example .env
docker compose up -d --build
```

Dashboard: [http://localhost:1880/dashboard](http://localhost:1880/dashboard)

Node-RED: [http://localhost:1880](http://localhost:1880)

Kafka UI: [http://localhost:8080](http://localhost:8080)

To see the messages:

```bash
docker exec -it iot_mosquitto mosquitto_sub -t "hospital/#" -v
docker exec -it iot_mosquitto mosquitto_sub -t "alerts/#" -v
```
